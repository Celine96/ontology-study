# M2. 속성 & 관계 — 개체를 잇기

> **목표**: 속성과 관계를 구분하고, 내 도메인의 관계망(누가 누구랑 이어지나)을 그린다.

## 한마디로

트리플의 가운데 칸(**서술어**)에는 **두 종류**가 있다 — 값을 가리키면 **속성**, 다른 것을 가리키면 **관계**.

::: tip 💡 쉽게 말하면 (반 친구로 비유)
민수라는 친구를 설명한다고 해봐요.
- "민수의 **키는 140cm**" → 키는 **숫자(값)**. 이런 건 **속성(Property)**.
- "민수의 **짝꿍은 영희**" → 짝꿍은 **다른 사람**. 이런 건 **관계(Relation)**.
한쪽은 값, 한쪽은 다른 개체. 이 차이만 알면 돼요!
:::

## 핵심 개념 — 두 종류의 서술어

1. **속성(Datatype property)**: 개체 → **값**(숫자·날짜·글자). `개최일 = "2026-10-17"`, `부스수 = 50`
2. **관계(Object property)**: 개체 → **다른 개체**. `참여기업A -운영→ 부스#12`, `부스#12 -위치→ 피지컬AI존`

> 영어 이름이 어려워 보이지만 뜻은 간단해요.
> - **Datatype property(데이터타입 프로퍼티)** = 값을 가리키는 서술어 (data = 자료/값)
> - **Object property(오브젝트 프로퍼티)** = 다른 개체를 가리키는 서술어 (object = 대상/개체)

관계에는 **방향**이 있고, **도메인/레인지** 라는 규칙이 있어요.
- **도메인(domain)** = "이 화살표가 **출발할 수 있는** 종류"
- **레인지(range)** = "이 화살표가 **도착할 수 있는** 종류"
- 예: `hostsAt`(~에서 열린다)의 도메인=Event, 레인지=Venue → "행사는 장소에서 열린다"만 허용. (행사→장소는 OK, 장소→사람은 X)

::: tip 💡 관계 이름이 설계의 절반
관계 이름을 잘 짓는 게 온톨로지 설계의 절반이에요. **동사처럼 짓고(운영한다, 위치한다), 방향을 분명히** 하세요.
:::

## onto-osint 대응 (그림 속 화살표 이름들)

리포트 그림(Mermaid)의 화살표에 붙은 영어가 바로 관계예요.

- `operates` (기관 → 이벤트): 누가 운영하나
- `hostsAt` (이벤트 → 장소): 어디서 열리나
- `partOfSeries` (이벤트 → 시리즈): 반복 프로그램의 한 회차
- `crossDongCombo` (이벤트 ↔ 이벤트): 같은 날 다른 동 연계 (`↔`는 "양쪽 방향" — 서로 이어짐)

## 실습 ✏️

M1에서 고른 부스 3개를 **관계 5개로 이어요.** 각 관계에 **도메인/레인지**(어디서→어디로 갈 수 있는지)를 적어요. 예: `promotes: Organization → Event`. 동그라미와 화살표로 그림도 그려보면 좋아요.
