# M2. 속성 & 관계 — 개체를 잇기

> **목표**: 속성과 관계를 구분하고, 내 도메인의 관계망을 설계한다.

## 핵심 개념 — 두 종류의 '서술어'를 구분하라

1. **속성(Datatype property)**: 개체 → **값(리터럴)**. `개최일 = "2026-10-17"`, `부스수 = 50`
2. **관계(Object property)**: 개체 → **다른 개체**. `참여기업A -운영→ 부스#12`, `부스#12 -위치→ 피지컬AI존`

관계엔 **방향**과 **도메인/레인지**(어떤 클래스→어떤 클래스만 연결 가능)가 있다.
예: `hostsAt` 의 도메인=Event, 레인지=Venue → "이벤트는 장소에서 열린다"만 허용.

## onto-osint 대응 (리포트 Mermaid의 화살표 라벨들)

- `operates` (기관 → 이벤트): 누가 운영하나
- `hostsAt` (이벤트 → 장소): 어디서 열리나
- `partOfSeries` (이벤트 → 시리즈): 반복 프로그램의 한 회차
- `crossDongCombo` (이벤트 ↔ 이벤트): 같은 날 다른 동 연계

::: tip 관계 이름이 설계의 절반
관계 이름을 잘 짓는 게 온톨로지 설계의 절반이다. **동사처럼 짓고 방향을 명확히.**
:::

## 서초 AI 페스타로 옮기면

```
참여기업A  -operates→  부스#12
부스#12   -locatedIn→  피지컬AI존
부스#12   -demos→      로봇(AITopic)
강연#3    -targets→    어르신(AgeGroup)
공동기획단  -promotes→   부스#12        ← 홍보/마케팅과의 연결고리
```

## 실습 ✏️

M1에서 만든 부스 3개를 **관계 5개로 잇는다.** 각 관계에 도메인/레인지를 적는다(`promotes: Organization → Event`처럼). 그림(노드+화살표)으로도 그려본다.
