# M1. 클래스 & 인스턴스 — 세상을 '종류'로 나누기

> **목표**: 클래스가 무엇인지 알고, 내 도메인의 클래스 트리(종류 나무)를 그린다.

## 한마디로

세상의 모든 것을 **클래스(종류)** 와 **인스턴스(진짜 하나)** 로 나눠서 본다.

::: tip 💡 쉽게 말하면 (포켓몬 도감처럼)
포켓몬 도감을 떠올려 봐요. "전기 타입 포켓몬"은 **종류(클래스)**, "내 피카츄 한 마리"는 **진짜 그 하나(인스턴스)**.
- **클래스(Class)** = 종류·무리 (전기 타입, 학생, 행사장)
- **인스턴스(Instance)** = 그 무리에 속한 진짜 하나 (피카츄, 민수, 서초문화예술공원)
:::

## 핵심 개념

- **클래스는 계층(taxonomy)을 이룬다.** 계층(택소노미)이란 **위아래로 묶이는 종류 나무**예요.
  예: `동물 ⊃ 포유류 ⊃ 강아지` (기호 `⊃`는 "~를 포함한다"는 뜻 — 동물 안에 포유류, 포유류 안에 강아지).
- 이 위아래 관계를 **is-a / 상위클래스(subClassOf)** 라고 해요. "강아지 is-a 동물".
- **왜 좋냐면 — 자동으로 물려받아요(상속).**
  "강아지는 동물이다"라고 한 줄만 적어두면, "동물은 숨을 쉰다"는 사실을 강아지가 **자동으로** 갖게 돼요. 일일이 다시 안 적어도 되죠. (이게 M3 **추론**의 씨앗이에요.)

::: tip 💡 용어 한 줄 정리
- **taxonomy(택소노미)** = 종류를 위아래로 묶은 나무 구조
- **subClassOf(서브클래스 오브)** = "~의 한 종류다" (강아지 subClassOf 동물)
- **상속** = 위(부모) 종류의 성질을 아래(자식)가 그대로 물려받는 것
:::

## onto-osint 대응

실습실 레포에선 클래스(틀)와 인스턴스(진짜 데이터)를 파일로 나눠서 저장해요.

- [`ontology/schema.json`](https://github.com/tykimos/onto-osint-yuseong-event/blob/master/ontology/schema.json) = **클래스/속성 정의** (틀) — "어떤 종류들이 있는지"
- [`ontology/instances.json`](https://github.com/tykimos/onto-osint-yuseong-event/blob/master/ontology/instances.json) = **실제 장소·기관 누적 DB** (붕어빵들) — "진짜 있는 것들"
- 핵심 클래스 위계: `Event → Venue → Dong`, 그리고 `Organization, Activity, AgeGroup`

> `schema(스키마)`는 "설계도·틀", `instance(인스턴스)`는 "그 틀로 만든 진짜 하나"라고 기억하면 돼요.

## 서초 AI 페스타로 옮기면

```
클래스 트리(종류 나무) 초안
- 행사(Event)
   └ 부스세션 / 강연 / 체험프로그램 / 공모전
- 공간(Venue)
   └ 전시존 / 피지컬AI존 / 무대
- 주체(Organization)
   └ 참여기업 / 기관 / 공동기획단
- 기술분야(AITopic)
   └ 생성형AI / 로봇(피지컬AI) / 음성 / 비전 ...
- 대상세대(AgeGroup)
   └ 아동 / 여성 / 장애인 / 어르신 / 가족전연령
```

## 실습 ✏️

위 클래스 트리를 **내 버전으로 다시 그려요.** 그리고 부스 3개를 골라 —
- 각 부스가 어느 **클래스(종류)** 의 **인스턴스(진짜 하나)** 인지 적고,
- 속성 2개씩(주최, 대상세대 등) 붙여요.
