# M3. 추론 — 온톨로지가 '똑똑한' 이유

> **목표**: 적어둔 사실과 컴퓨터가 알아낸 사실을 구분하고, if-then 추론 규칙을 직접 써본다. (이게 실습실 레포의 알맹이예요.)

## 한마디로

**추론(reasoning)** = 적어두지 않은 사실까지 컴퓨터가 **스스로 알아맞히는 것**.

::: tip 💡 쉽게 말하면 (탐정처럼)
"민수는 강아지를 키운다" + "강아지는 동물이다" 이 두 개만 적어두면 →
컴퓨터가 **"아! 민수는 동물을 키우는구나"** 라고 스스로 알아내요. 아무도 그 문장을 직접 안 적었는데도요.
이렇게 **숨은 사실을 찾아내는 게 추론**이에요. 셜록 홈즈가 단서로 범인을 맞히는 것처럼요.
:::

## 핵심 개념 — 적지 않은 사실을 컴퓨터가 만든다

- **명시적 사실** = 내가 직접 적은 트리플. (명시적 = "대놓고 적어둔")
- **추론된 사실** = 규칙을 따라 컴퓨터가 **새로 만들어낸** 트리플.

추론에는 이런 종류가 있어요.

- **상속**: "전시홀은 실내공간이다" + "실내공간은 비 와도 OK" → "전시홀은 비 와도 OK" (자동)
- **규칙(if-then)**: "**만약** 같은 동·같은 날 행사 둘이면 → **그러면** 묶어서 추천해라"
- **전이(transitive)**: A-옆-B, B-옆-C → A-옆-C ("옆의 옆은 가까운 사이")

> **if-then(이프-덴)** = "만약 ~이면, 그러면 ~해라"라는 규칙 형식. 우리가 평소 "비 오면 우산 챙겨"라고 하는 것과 똑같아요.

## onto-osint 대응

[`CLAUDE.md`](https://github.com/tykimos/onto-osint-yuseong-event/blob/master/CLAUDE.md) 파일과 [리포트의 "추론 결과"](https://github.com/tykimos/onto-osint-yuseong-event/blob/master/reports/2026/05/2026-05-23.md)에 이런 규칙들이 들어 있어요. (`↑`는 "점수가 올라간다"는 뜻)

- **`same_dong_combo`** — 같은 동·같은 날 행사를 같이 가기 좋게 묶기 · 신뢰도 **0.92**
- **`same_date_cross_dong`** — 같은 날 다른 동 행사를 이어서 추천 · 신뢰도 **0.80**
- **`operator_kid_friendliness`** — 도서관·과학관이 주최하면 어린이 적합 점수가 올라감(↑) · *(신뢰도 점수 미부여)*
- **`indoor_rainy_fallback`** — 비 오면 같은 동 실내 행사로 대신 추천 · *(신뢰도 점수 미부여)*

::: info 💡 꼭 보고 갈 것 — 신뢰도(confidence) 점수
추론마다 **신뢰도 점수(0~1)** 가 붙어요. 1에 가까울수록 "꽤 확실", 0에 가까울수록 "그냥 추측".
컴퓨터가 100% 확신하는 게 아니라 **"얼마나 그럴듯한지 별점"** 을 매기는 거예요. 추천 순서를 정할 때 이 점수가 기준이 돼요.
:::

- (홍보) `promo_priority` : 화제성 큰 부스(피지컬AI·공모전 등)는 홍보 우선순위 올라감(↑)

## 실습 ✏️

서초용 추론 규칙 **2개**를 이 형식으로 직접 써요:

```
if ( 조건 )  then ( 새로 만들 트리플 )  [신뢰도]
예) if (부스가 피지컬AI존에 있다)  then (그 부스 = 추천후보)  [0.85]
```

그중 1개는 **기획단 홍보 업무**와 연결되게 만들어요.
