# 부록 — 표준·도구 & 진도표

## 더 깊이 — 표준과 도구 (지금 당장은 몰라도 됨)

::: tip 💡 먼저 안심하세요
아래는 "더 깊이 들어가고 싶을 때" 쓰는 **전문 도구 이름들**이에요. 지금은 **이런 게 있구나** 정도만 알면 충분해요. 우리 프로젝트(M0~M5)는 쉬운 JSON으로 충분히 돌아가요.
:::

onto-osint는 JSON으로 만든 **실용 온톨로지**예요. 나중에 더 전문적으로 가려면 이런 표준·도구가 있어요:

| 키워드 | 쉬운 풀이 | 언제 필요? |
|---|---|---|
| **RDF** | 트리플(세 칸)을 적는 **세계 공통 약속 표기법** | 데이터를 남과 주고받거나 공개할 때 |
| **RDFS / OWL** | 클래스·관계·추론을 **아주 엄격하게** 정의하는 언어 | 빈틈없는 추론·검증이 필요할 때 |
| **SPARQL** | 지식그래프에 질문을 던지는 **검색 언어** (엑셀 필터의 그래프 버전) | 그래프에서 복잡하게 찾고 싶을 때 |
| **Protégé** | 온톨로지를 **마우스로 그려 만드는** 프로그램 | OWL로 본격 설계할 때 |
| **Neo4j** | 거대한 지식그래프를 담는 **전용 데이터베이스** | KG가 아주 커졌을 때 |

> 영어 이름이 어렵지만, 결국 다 **"트리플을 더 정확하게 적고·찾고·저장하는"** 도구들이에요.

::: tip 학습 순서 추천
M0~M5(실용)로 감각을 먼저 만들고 → 필요할 때 RDF/OWL로 "형식화" → SPARQL로 "질의". **표준부터 들어가면 대부분 중도 포기한다.**
:::
